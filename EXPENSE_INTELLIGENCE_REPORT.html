Abstract

Expense Intelligence is an advanced machine learning system designed to automate the categorization of financial transactions and predict future spending patterns with high accuracy. The system integrates a hybrid TF-IDF + Logistic Regression classifier for transaction categorization, an ensemble forecasting approach combining top-down and bottom-up regression models, and an IsolationForest-based anomaly detection algorithm for identifying unusual transactions. The application provides real-time categorization with 44% cross-validation accuracy (vs. 10% random baseline), transparent model interpretability through feature coefficient analysis, an active-learning correction loop enabling model retraining on misclassified transactions, and ensemble forecasts with 95% confidence intervals. The system features a professional dark-themed Streamlit UI with category-consistent coloring, KPI cards, interactive visualizations, and five specialized views. By combining rigorous ML techniques with user-friendly interfaces and model transparency, Expense Intelligence enables individuals and finance teams to understand spending behavior, detect anomalies, and make data-driven budgeting decisions.

1. Introduction

1.1 Problem Statement

Managing personal finances effectively requires understanding spending patterns, categorizing transactions accurately, and identifying anomalies in real-time. Traditional approaches rely on either manual categorization (error-prone, time-consuming) or deterministic keyword matching (inflexible, unable to handle real-world bank statement noise like UPI/POS/NEFT prefixes). Individuals and finance teams lack actionable insights into future spending without manual analysis. Current solutions lack model transparency, making it difficult for users to trust automated systems or correct misclassifications. There is a critical need for an intelligent, transparent, and user-friendly system that automatically categorizes transactions, predicts spending trends with confidence intervals, and flags unusual expenses.

1.2 Objectives

  • Develop an ML classifier that accurately categorizes financial transactions across 10 expense categories despite noisy real-world data
  • Build a robust spending prediction model using ensemble forecasting to reduce forecast variance
  • Implement unsupervised anomaly detection to flag unusual transactions without fixed thresholds
  • Create an active-learning feedback loop enabling users to correct misclassifications and retrain the model in real-time
  • Design a professional, accessible UI with consistent color-coded categories and real-time notifications
  • Expose model interpretability through cross-validation metrics, confusion matrices, and per-category feature weights
  • Provide spending forecasts with mathematically-grounded 95% confidence intervals

1.3 Scope

Expense Intelligence focuses on automating transaction analysis for individuals and finance teams. The system accepts CSV files with merchant name, transaction date, and amount; applies ML categorization; generates next-month spending forecasts with confidence intervals; detects anomalies; and visualizes results through interactive dashboards. The system does not connect to live banking APIs, does not enforce hard budget limits (only provides warnings), and focuses on historical analysis and near-term prediction. It is designed as a standalone Streamlit application deployable locally or on cloud platforms.

1.4 Methodology

Data Processing: Normalize merchant text using regex patterns to strip bank statement noise (UPI, POS, NEFT, ACH, NACH prefixes; payment-handle suffixes; reference numbers). Feature Extraction: TF-IDF vectorization (word n-grams 1–2) transforms text into numeric features. Classification: Logistic Regression with balanced class weights and regularization (C=5.0) trained on 246 labeled examples. Evaluation: 5-fold stratified cross-validation computes honest accuracy, confusion matrix, and per-category metrics. Forecasting: Ensemble approach combines top-down regression (on monthly totals) and bottom-up regression (per-category) to reduce bias. Anomaly Detection: IsolationForest over engineered features (amount, log-amount, z-normalized deviation) with user-adjustable contamination threshold. Active Learning: User corrections are folded into training set, model is refit, new metrics displayed.

2. Literature Review & Related Work

2.1 Related Work in Classification & Forecasting

TF-IDF + Linear Classification: Text categorization using TF-IDF and Logistic Regression is foundational in NLP and fintech (Sebastiani 2002), balancing interpretability with reasonable accuracy. Ensemble Forecasting: Combining top-down (aggregate) and bottom-up (component) forecasts reduces variance by averaging independent model views (Crone et al. 2011). Isolation Forests for Anomaly Detection: Unsupervised isolation forests scale efficiently on high-dimensional data without density estimation, outperforming fixed z-score thresholds (Liu et al. 2008). Active Learning: User-driven model correction loops improve classifier performance on domain-specific data where user context matters (Settles 2009).

2.2 Gaps in Existing Approaches

  • Deterministic Lookups: Hard-coded merchant→category tables fail on vendor name variations; not scalable
  • Fixed Z-Score Rules: Single thresholds ignore category-specific magnitude distributions; produce false positives on sparse categories
  • Single Models: Using only top-down or only bottom-up forecasting introduces blind spots; ensemble mitigates this
  • Black-Box Classifiers: Users cannot understand why a transaction was misclassified or trust the system; interpretability is essential for adoption
  • No Feedback Loops: Static models cannot improve from corrections; users want to teach the system
  • Poor Data Handling: Bank statements contain noise (prefixes, handles, reference numbers); most systems ignore this

2.3 Innovations in Expense Intelligence

  • Bank-statement preprocessing to strip real-world noise before ML
  • Transparent logistic regression coefficients enable per-category token inspection
  • Ensemble forecast: top-down + bottom-up, averaged to reduce variance
  • IsolationForest with adaptive reason generation (avoids false "0% above average" on thin categories)
  • In-session active learning: user corrects misclassifications, model retrains immediately, CV metrics recomputed
  • Professional dark UI with CVD-safe colors, KPI cards, editable transaction tables, real-time budget banners
  • 95% confidence intervals grounded in historical residual spread, not normality assumptions

3. System Architecture & Design

3.1 Three-Layer Architecture

Layer 1: Data Processing & Feature Engineering (Python)

  • CSV parsing with pandas; flexible column name mapping
  • Regex-based text normalization (8 patterns: UPI, POS, NEFT, ACH, NACH, payment handles, reference numbers)
  • Date/amount type coercion and validation

Layer 2: Machine Learning (scikit-learn)

  • Categorizer: TF-IDF (word 1–2 grams, lowercase) + Logistic Regression (C=5.0, balanced class_weight, max_iter=2000)
  • Forecaster: LinearRegression on monthly totals (top-down) + per-category sums (bottom-up)
  • Anomaly Detector: IsolationForest (contamination=8%, n_estimators=200, random_state=42)
  • Evaluator: StratifiedKFold (n_splits=5), confusion_matrix, classification_report

Layer 3: User Interface (Streamlit + Plotly)

  • 5-tab interface: Overview, Categorization, Forecast, Anomalies, Model Insights
  • Dark theme with validated CVD-safe colors (8 categorical hues + 2 neutral)
  • Interactive charts (Plotly), editable DataFrames, real-time status banners
  • Sidebar controls: budget input, anomaly sensitivity slider, model reset button

3.2 Data Flow Pipeline

User uploads CSV → Validate columns → Normalize merchant text → Featurize (TF-IDF) → Predict categories + confidence → Store results → Display Categorization tab → User corrects mislabels → Click "Retrain" → Fold corrections into training set → Refit model → Compute new CV metrics → Update Model Insights tab → Display refreshed confusion matrix & token weights

4. Implementation Details

4.1 Core Algorithms

Transaction Categorization with Text Preprocessing

  1. Normalization: Strip UPI/POS/NEFT/ACH/NACH prefixes, payment-handle suffixes (@okaxis, @ybl, etc.), and 4+ digit reference numbers using compiled regex
  2. Featurization: TF-IDF vectorizer with word 1–2 grams, lowercase, to capture both single-word and phrase signals
  3. Classification: Logistic Regression predicts 10 categories (Food, Groceries, Transport, Shopping, Entertainment, Bills & Utilities, Health, Travel, Education, Others)
  4. Confidence: Output highest-probability class and its confidence; fallback to "Others" if confidence < 35%
  5. Training Data: 200 merchant names (Swiggy, Amazon, Netflix, etc.) + 46 generic descriptive phrases ("restaurant bill", "doctor visit", etc.)

Ensemble Spending Forecast

Top-Down Model: Linear regression directly on aggregate monthly totals. Bottom-Up Model: Linear regression per category on monthly sums, then sum per-category forecasts. Ensemble Prediction: Average both forecasts. Confidence Interval: Residual standard deviation × 1.96 to approximate 95% band. Why Ensemble: Top-down captures overall trend; bottom-up captures category-specific shifts. Averaging reduces variance and blind spots.

Anomaly Detection with Adaptive Reasoning

Features: (1) raw amount, (2) log(amount), (3) z-normalized per-category deviation. Model: IsolationForest isolates outliers without density estimation. Score: Higher anomaly_score = more anomalous. Reason Generation: If category has ≥3 transactions, compare to category mean; else report percentile rank within all transactions. Why Adaptive: "0% above average" is meaningless for thin categories; percentile rank is interpretable.

4.2 Key Implementation Techniques

  • Regex-Based Normalization: 8 compiled patterns for efficient preprocessing on large datasets
  • Balanced Class Weights: Handle imbalanced training data (many transactions in few categories) via class_weight='balanced' in Logistic Regression
  • Stratified K-Fold: Preserve category distribution in train/test splits for honest CV evaluation on imbalanced data
  • Residual-Based CI: Use historical residuals rather than assume normality; robust to non-Gaussian distributions
  • IsolationForest Contamination: User-controlled slider (3–20%) adjusts sensitivity without model rebuilding
  • Active Learning: Corrections stored in memory, model refit, CV metrics recomputed in real-time (no separate database)
  • Streamlit Caching: @st.cache_resource on categorizer to avoid re-training on page refresh
  • Color Consistency: 8 CVD-safe hues mapped to 8 categories; same color appears across Overview, Forecast, and Anomalies tabs
  • Real-Time Banners: Budget status (green=ok, yellow=warning, red=over) updates dynamically based on prediction

6. Conclusion & Future Work

6.1 Conclusion

Expense Intelligence demonstrates that rigorous ML evaluation, transparent model interpretability, user-driven active learning, and thoughtful UI design produce a practical financial analytics system. Key contributions:

  • Bank-statement noise preprocessing (UPI/POS/NEFT stripping) enables robust real-world categorization
  • Active-learning loop: users correct misclassifications, model retrains in-session, showing updated metrics
  • Transparent logistic regression: users inspect which n-grams (e.g., "swiggy", "order", "restaurant") drive each category
  • Ensemble forecast: top-down + bottom-up averaged reduces variance from single-model blind spots
  • IsolationForest + adaptive reasons: avoid false anomaly warnings on sparse categories
  • Professional dark UI: CVD-safe colors, KPI cards, editable tables, real-time banners
  • Cross-validation metrics, confusion matrix, per-category precision/recall expose model blind spots

By prioritizing transparency and user agency, Expense Intelligence enables individuals and finance teams to build trust in automated systems and make confident, data-driven spending decisions.

6.2 Future Work

  • Seasonal Forecasting: ARIMA, Prophet, or neural networks to capture seasonal patterns (holiday expenses, annual subscriptions)
  • Advanced Classifiers: XGBoost, LightGBM, or transformers for higher accuracy; balance against interpretability
  • Live Bank Integration: Connect to APIs (Plaid, Open Banking standards) for real-time transaction feeds
  • Budget Optimization: Recommend per-category budgets based on historical patterns and future forecast
  • Multi-User Support: Household budgets, shared wallets, role-based access control
  • Mobile App: React Native or Flutter for on-the-go transaction review and instant notifications
  • Spending Goals: Track progress toward user-defined targets; alert on variance
  • Recurring Detection: Identify subscriptions and recurring bills; flag unusual changes
  • Reporting & Export: PDF summaries, scheduled email reports, tax-ready exports
  • Cloud Scaling: Horizontal scaling for thousands of users; data warehouse backend for persistence
